## 硬件实测：单核 EPYC 9655，顺序读写 1GB/s，4K 随机读只有 5–6MB/s

同型号两台机器在 2026 年 10 月 28 日各有一份公开的硬件体检报告，数据可以互相印证，也暴露了一个前排测评很少直说的问题。

CPU 识别为 AMD EPYC 9655 96-Core Processor（步进 1），分配到 1 核 1 线程、2596MHz，L3 缓存 16MiB，支持 AES-NI、AVX2、BMI1/2。Sysbench 单线程两台分别是 5122 和 5174；Geekbench 5 单核 1962 / 1885，多核 1909 / 1905。1 核机器多核分与单核接近是正常的，别把这个当成跑分异常。

内存实报总容量 **1.9GB**，不是标称的 2GB，另有 1024MB swap。内存带宽读 84–88GB/s、写 33GB/s、延迟 121–124ns，DDR5 的水平。

磁盘是最值得注意的一项：

- 顺序读写 SEQ1M Q8：读 1010MB/s、写 1051MB/s，跑满千兆口没问题
- 4K 随机读 Q32：89.7MB/s，约 23k IOPS
- **4K 随机读 Q1：只有 5.6–6.0MB/s，1.4k–1.5k IOPS**

这个差距意味着：传大文件、拉镜像、跑顺序读写型的任务，体验很好；MySQL 这类小文件随机读密集的负载，会明显受限。综合评分里硬盘分项排名只有 4.3%，和这组 4K 数据互相印证。整机加权总分两台分别是 46022 和 50851，排名 16.0% 和 19.3%。

还有一处不同：一台机器显示「气球回收 ✔」，另一台显示「✘」，KSM 复用两台都是否。同型号不同宿主机配置不一致，说明内存气球在部分宿主机上是开着的。对 2GB 内存的机器来说，这意味着极端情况下可用内存可能被进一步压缩——1 核 2G 的机器本来就该按「跑一个轻量服务」来规划。

## 1TB 流量和 4Mbps 限速，实际是什么体验

流量双向计算，进和出都算。1000GB 对单人使用是很宽的额度，对建站就没那么宽：一个日 PV 几千的图文站，加上系统更新、备份、日志同步，一个月跑掉几百 GB 很常见。

跑满之后不关机、不断线，限速到 **4Mbps**。换算一下，4Mbps 约等于 500KB/s，一个 1MB 的页面要两秒，图片多的站会明显变慢，SSH 操作不受影响。

这个设计比硬停机好得多。以前超流量意味着站点半夜直接挂掉，现在最坏情况是「这个月剩下的时间网站变慢」，不会丢数据也不会丢访问。但反过来，如果你预估月流量会经常超过 1TB，那 4Mbps 撑半个月也很难受，该上 STARTER 的 3000GB。

Pocket 同样是 4Mbps 超量限速，STARTER 也是 4Mbps；到 MINI / MICRO 提升到 8Mbps，MEDIUM 及以上是 10Mbps。想靠超量限速当「无限流量低速机」用的话，档位越高越舒服。

## 线路：IPv4 回程 CN2 GIA，IPv6 走 9929 / CMIN2

洛杉矶 Pro 是双栈优化：IPv4 回程走 CN2 GIA，IPv6 走 9929 / CMIN2。DMIT 在 Pro 档上还配置了对三网（AS4809 / AS9929 / AS58807）的专用互联。中国大陆方向延迟常在 150–200ms，电信路径最干净，实测常在 150ms 左右，联通和移动略高。

晚 8 点到 11 点的高峰期，Pro 的丢包明显低于普通中转，原因是流量走专用互联，绕开了拥堵的公共网关。这部分溢价买的就是高峰期不掉速。

机房侧是 CoreSite 与 Digital Realty 园区、Tier IV 标准、N+1 供电与制冷、7×24 现场安保，以及 ISO 27001 / SOC 2 / PCI DSS 合规，聚合 Tier 1 传输容量最高 3.8Tbps。这些是底座信息，不直接改变你的使用体验，但能解释为什么同配置它比普通美西机器贵。

## IP、流媒体与 25 端口：原生 IP 解锁不错，但不能自建发信

IP 归属组织是 DMIT Cloud Services，标注为原生 IP。多个 IP 库把它判为机房使用类型，风险评分普遍偏低：IP2Location 3、Scamalytics 3、AbuseIPDB 0；ipapi 给了一个 1.95% 的「较高风险」，是几个库里唯一偏高的。风险因子中代理、Tor、VPN、滥用、机器人全部为否，只有「服务器」一栏在多数库里标「是」——机房 IP 本来就这样。

流媒体和 AI 的解锁情况（两份报告结论一致，地区均为 US）：

- TikTok、Disney+、YouTube、Amazon Prime Video、ChatGPT：解锁
- Netflix：走 DNS 方式解锁
- Reddit：屏蔽

需要注意，解锁状态随平台封禁名单变化，DMIT 官方也不把解锁当卖点。今天能看，不保证三个月后还能看。

邮局是明确的短板：本地 25 端口出站阻断，远端 25 端口不可达。黑名单库里 423 条记录中，一台机器 421 条正常、2 条被标记，另一台 400 条正常、23 条被标记，两台都没有被拉黑。IP 本身不脏，但 25 端口封了，想发信只能用外部 SMTP 中继（比如企业邮箱服务商或事务性邮件 API）。自建 Postfix 直接发信这条路走不通。

## Pro 和 EB 怎么选

EB（Eyeball）走 CMIN2 的中国路由，官方措辞是「reasonable effort」，定位低于 Pro。有一条资料称 EB TINY 给 1.5TB 流量 / 2Gbps 端口，而 Pro TINY 是 1TB / 1Gbps，且「价格差已经不大」——这组数字只有单一来源，和另一些资料对 EB 定位的描述也不完全吻合，当作参考就好，具体参数请自己在官网核对。

从定位上判断更可靠：电信用户晚高峰的体验差异在 Pro 和 EB 之间最明显，Pro 的 CN2 GIA 更稳；移动用户两者差距小，EB 的性价比更高。如果你的访客以移动网络为主，多花钱买 Pro 的收益没有想象中大。

## 谁不该买这台

三类人可以直接排除：

- **用户全在欧美**：你付的是中国方向的路由溢价，普通的美西按量计费机器更省钱
- **要跑数据库或高并发**：1 核 2G、4K 随机读 5–6MB/s，这是硬约束，不是调优能解决的
- **预算卡在 $10 以下还想要 10Gbps**：这个组合在 Pro 线里不存在，TINY 是 1Gbps

按场景选的话：

| 你要做的事 | 选哪个 |
| --- | --- |
| 个人 SSH、轻量代理、临时测试 | TINY |
| 面向中国大陆的小站或 API | STARTER（80G 盘、3TB 流量、10Gbps） |
| 需要 4 核跑应用 | MINI |
| 有真实并发的生产环境 | MEDIUM |
| 需要 8 核以上 | LARGE / GIANT 目前缺货，只能等补货，或两台 MEDIUM 做负载均衡 |

TINY 的 20GB 磁盘是最先撞到的墙：系统占几个 G，日志和备份再吃几个 G，剩下能放业务数据的空间不多。装个 Docker 再拉两个镜像就紧张了。这是升级到 STARTER 最实在的理由，比流量更实在。
